# Архитектура проекта

Дата: 2026-09-02  
Статус: `active`

## Основное решение

Игра остаётся HTML5-приложением на `React 19 + TypeScript + Vite`. Unity и полный перенос в Phaser не требуются: враги статичны, а текущие пули, попадания, монеты и числа урона укладываются в CSS/DOM либо лёгкий Canvas-слой.

## Структура

| Путь | Ответственность |
|---|---|
| `src/game/Game.tsx` | Экран игры, состояние представления, эффекты и действия игрока |
| `src/game/clickerV3.ts` | Главная математика, экономика, зоны, оружие и нормализация сохранений |
| `src/game/dungeonChallenges.ts` | Данжевые испытания |
| `src/styles/game.css` | Общий UI, responsive и визуальные состояния |
| `src/platform/` | Интеграция конкретной площадки |
| `Modules/` | Независимые от React сервисы аналитики, аккаунта, рейтинга и сохранения |
| `public/art/` | Только используемые оптимизированные игровые ассеты |
| `public/audio/` | Используемые звуки |
| `public/fonts/` | Локальные шрифты и лицензии |
| `tests/` | Регрессии механик и UI-контрактов |
| `scripts/` | Сборка и упаковка платформенных версий |

## Архитектурные правила

- Игровая математика не вызывает SDK площадок.
- Компоненты не должны напрямую обращаться к GamePush и Poki после введения общего platform facade.
- У каждой площадки отдельная сборочная конфигурация; SDK разных платформ не смешиваются.
- Сохранение имеет версию схемы и миграцию.
- Аналитические события используют стабильные технические имена.
- Ассеты распределяются по биомам и загружаются постепенно.
- Внешние ключи и секреты не входят в клиентский код.

## Следующая архитектурная работа

Перед Poki-релизом прямые обращения `Game.tsx → gamePush` необходимо заменить единым platform facade с реализациями `local`, `gamepush` и `poki`. Подготовленные переносимые контракты уже находятся в `Modules/`.
