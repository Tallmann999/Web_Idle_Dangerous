# Состояние, переходы, сохранения

## Два вида времени

Время боя тикает только при активной арене. Шаг 0,2 секунды, без ускоренного догоняющего расчёта после скрытия приложения. Таймер босса и автоурон используют это время. После убийства пауза 450 мс также приостанавливает начисление автоурона.

Боевой настрой использует абсолютные метки времени: конец действия = активация +15 с, следующая готовность = активация +615 с. Переключение окна, выход в гильдию и закрытие приложения не продлевают эффект.

## Сохраняемые данные

Машиночитаемый пример новой игры — `06_DATA/fresh-save.json`, пример развитого тестового профиля помечен TEST-ONLY и не должен использоваться при первом запуске.

| Поле | Смысл |
|---|---|
| version | Версия схемы, сейчас 1 |
| gold / diamonds | Независимые кошельки золота и алмазов |
| room / highest | Текущий уровень и наибольший открытый |
| kills | Убийства в текущем цикле, 0–9 |
| serial | Общий серийный номер, участвует в выборе изображения и HP |
| hp | Текущее здоровье противника |
| bossTime | Оставшееся активное время попытки; при загрузке босса сбрасывается |
| defeated | Номера побеждённых боссов |
| gear | По стабильному ID вещи: level и список купленных рубежей upgrades |
| clickLevel | Уровень тренировки, 0–999 |
| inventory | По ID компонента: count и value всей партии в алмазах |
| location | dungeon или guild |
| reputation / totalKills | Репутация и общее число убийств |
| completed | Побеждён финальный босс |
| offerRoom / offerHp | Незавершённое предложение повторить проигранного босса |
| rescueUsed / boost | Использовано ли рекламное продолжение, активен ли ×2 DPS |
| focusUntil / focusReady | Конец настройки и момент следующей готовности, миллисекунды календарного времени |
| sound | Общая настройка звука |

Окна, выбранная вкладка инвентаря, текущий слот прокачки, счётчик анимации удара и визуальные эффекты не нужно восстанавливать как часть экономики. Пакет покупки по умолчанию ×1, сам выбор пакета не сохраняется.

В web-эталоне сохранение локальное под ключом `idle-dangerous-save-v1`. Для другого движка формат хранения можно заменить, но смысл полей и транзакций надо сохранить. Старые сохранения Clicker Weapon Adventure не относятся к этой игре.

## Когда записывать

Покупка/тренировка/рубеж, убийство, переход комнаты, переход в гильдию/обратно, торговля, переключение звука, активация настройки; также скрытие/закрытие приложения и периодическая запись изменённого состояния раз в 15 с. Успешное начисление и удаление товара — одна операция, без окна для повторного получения награды.

При ошибке записи показать предупреждение и продолжить текущую сессию. Не заявлять пользователю, что прогресс гарантированно сохранён, если запись не удалась.

## Загрузка и восстановление

- Неверная версия/повреждённый объект дают новый профиль; частично неверные числа ограничиваются допустимым диапазоном.
- Старое сохранение схемы 1 без diamonds получает 0 алмазов, остальная экономика остаётся.
- room ограничивается 1…highest, highest — 1…105. Побеждённые боссы восстанавливаются по пройденным порогам; completed учитывается только при highest=105.
- Если сохранённое место — уже побеждённый босс, выбрать предыдущий обычный уровень.
- Шлем не ниже уровня 1. Уровни вещей/тренировки не выше 999. Купленные рубежи только из 10/25/50/100/150 и не выше уровня вещи.
- Для обычного врага HP ограничивается 1…максимум. Прерванный бой босса начинает новую попытку с полным HP и 30 с; рекламный ×2 и окно поражения не восстанавливаются.
- У пустого стека value=0. Отрицательные/нечисловые деньги и количества не допускаются. В текущем источнике большинство больших чисел ограничивается 1e100, count компонентов — 1e12, serial — 1e9.
- Офлайн-дохода и офлайн-убийств нет. Достаточно восстановить мир, валюты и состояние, затем ждать входа игрока.

## Числа при переносе

Поздняя кампания достигает очень больших величин. 32-битные целые и обычный float не подходят для точного повторения расчётов. Исходные вычисления используют 64-битную плавающую точку и округление положительных чисел Math.round (половина вверх). В целевом движке нужно явно сохранить эквивалент этого округления: стандартное «к ближайшему чётному» может дать другие цены. Сверять `balance-reference-values.json` и `levels.json`.

Общее форматирование HUD: русская локаль, компактные обозначения с 10 000; числа ≥1e15 — экспоненциальная запись с двумя знаками; ниже 10 допускается десятая доля. Число урона имеет отдельное компактное форматирование с одной десятичной. Разделители и шрифтовые глифы зависят от платформы, но единицы валют и смыслы должны остаться.
