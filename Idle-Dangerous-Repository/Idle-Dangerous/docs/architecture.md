# Архитектура Idle Dangerous

Phaser 4.2.1 + React 19 + TypeScript + Vite. Phaser отвечает за боевую сцену, часы боя, ввод мышью/касанием, звук, загрузку текстур и эффекты. React отображает HTML-интерфейс и передаёт сцене доступ к существующему состоянию. WebGL выбирается автоматически, Canvas — запасной режим.

| `src/idle/Game.tsx` | Вертикальный HTML-интерфейс, окна, сохранение и платформенные события |

## Состояние и сохранение

Новый независимый localStorage-ключ: `idle-dangerous-save-v1`, схема 1. Старые weapon-save не читаются и не перезаписываются. Это новая игра, поэтому первый вход начинает её с нуля.

Сохраняются золото, текущая и максимальная комната, счётчик убийств, HP обычного врага, экипировка с рубежами, уровень клика, компоненты с суммарной стоимостью, репутация, местоположение (гильдия/подземелье), прохождение финала, звук и таймеры настройки.

Запись: покупки, убийства, смена комнаты/места, продажа, скрытие вкладки, `pagehide`, резервный интервал 15 секунд. Ошибки localStorage показываются игроку без прекращения игры. При загрузке числовые поля ограничиваются; некорректный или чужой формат даёт новое состояние.

Прерванная попытка босса начинается заново. Межсессионного урона и offline-дохода нет. Таймеры «Настроя» основаны на календарном времени, время боя — на активной симуляции.

## Паузы

Инвентарь, путь, тренировка, помощь, гильдия, стартовый экран, реклама, скрытая вкладка, загрузка ресурсов и сцена победы приостанавливают симуляцию. Окно экипировки не останавливает бой. Lifecycle платформы следует этому состоянию. Phaser переиспользует звук попадания и ограничивает VFX шестью контейнерами. Симуляция работает с прежним шагом 200 мс, без накопления времени скрытой вкладки; после убийства сохраняется задержка 450 мс.

При переходе в другой ярус сцена загружает его фон, весь пул врагов и боссов. В памяти остаются не более двух ярусов. Смена врага использует прежнюю формулу `room * 3 + serial`, изображения не рандомизируются заново при перерисовке HTML. Исходные листы предметов имеют нерегулярную сетку: они нарезаются заранее, а не интерпретируются как кадры анимации.

При выходе в гильдию Phaser.Game освобождается; при возврате создаётся из сохранённого состояния. ResizeObserver и обработчики сцены удаляются вместе с игрой. Клавиатурная кнопка атаки передаёт команду в ту же сцену, что и указатель Phaser.

## Платформы

`npm run build` создаёт локальный web-build. `npm run build:poki` выбирает `.env.poki`, подключает сохранённый platform bridge и Poki SDK, исключает GamePush из Poki-бандла. На локальной сборке нет имитации успешной рекламы. Плагин Vite копирует только ресурсы текущей игры, исключая исходные PNG-листы, оружие и карты старого проекта; Phaser вынесен в отдельный JS-бандл. Относительные URL поддерживают размещение в подпапке.

Новая игра хранит прогресс локально в отдельном ключе. Верификация платформенной облачной синхронизации, аккаунтов, аналитики новой экономики и таблиц лидеров не выполнена. GamePush cloud save новой схемы к интерфейсу не подключён. Старый инфраструктурный код сохранён как заготовка и не является подтверждением готовности этих функций.

Публикация на Poki не выполнялась. Перед релизом нужны проверка текущих требований площадки, Inspector, реальная реклама и тест на телефоне. В проекте не следует использовать данные старого Sites-проекта: это самостоятельный локальный форк, предназначенный для скачивания.
