# Перенос Idle Dangerous в новый репозиторий

1. Распакуйте архив. Откройте папку `Idle-Dangerous` — в ней уже находятся `package.json`, `src/` и `docs/`.
2. Создайте пустой репозиторий GitHub. Не создавайте в нём начальные README и .gitignore: эти файлы уже есть в проекте.
3. Откройте терминал в папке `Idle-Dangerous` и выполните:

```sh
git init
git add .
git commit -m "Initial Idle Dangerous project"
git branch -M main
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

Замените адрес после `origin` на адрес своего нового репозитория.

## Локальный запуск

```sh
npm ci
npm run dev
```

Нужен Node.js 22.13+; рекомендуется 24. На Windows также есть `START-DEV.cmd`.

## Что включено

- `src/idle/` — текущая новая игра: вертикальный бой, экипировка, добыча, гильдия.
- `src/game/` и `Modules/` — сохранённые исходные модули; новый экран запускается из `src/idle/Game.tsx`.
- `public/` — игровые ассеты, звуки и шрифты.
- `docs/` — актуальные концепт, баланс, архитектура, миграция, QA и скриншоты; старая документация находится в `docs/legacy-clicker-weapon/`.
- `tests/` — проверки, в том числе новая логика в `tests/idle/`.
- `dist/` — готовая локальная web-сборка.
- `release/` — отдельные локальная и Poki ZIP-сборки.
- `preview/idle-dangerous.html` — историческое превью до переноса на Phaser.

В архиве нет истории `.git`, `node_modules` и привязки старого сайта. Новый репозиторий создаётся независимо.

`.gitignore` исключает `dist/` и `release/`: они входят в этот архив, но не попадут в первый коммит. Их можно заново получить командами `npm run release:local` и `npm run release:poki`. Для скачивания сборок из GitHub их удобно приложить к GitHub Release.

## Откуда продолжать

Сначала прочитайте `docs/README.md`, затем `docs/project-concept.md` и `docs/balance.md`. Основная версия — Phaser 4 с HTML-интерфейсом React. Однофайловое превью содержит сокращённый набор монстров и фонов ради размера, использует отдельное сохранение и служит демонстрацией той же механики.

Проверки, выполненные при сборке, перечислены в `docs/QA.md`. Поздняя экономика, реальные мобильные устройства и платформенные интеграции остаются предметом дальнейшей проверки. Публикация на площадках не выполнялась.
