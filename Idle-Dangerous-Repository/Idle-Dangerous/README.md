# Idle Dangerous

Вертикальная браузерная игра на базе предоставленного проекта Clicker Weapon Adventure.

**Монстры → золото и компоненты → экипировка → глубина → гильдия → новый спуск.**

## Быстрый запуск

Нужен Node.js 22.13+ (рекомендуется Node.js 24).

```sh
npm ci
npm run dev
```

Откройте адрес, показанный Vite. На Windows можно запустить `START-DEV.cmd`.

## Готовая игра

Папка `dist/` содержит собранную локальную web-версию. Её нужно открывать через HTTP-сервер, а не двойным кликом по `index.html`:

```sh
npm run preview
```

На Windows после установки зависимостей: `START-PREVIEW.cmd`.

В папке `release/` находятся отдельные ZIP только с web-сборкой. В них `index.html` лежит в корне. Архив `idle-dangerous-local.zip` предназначен для обычного статического хостинга; `idle-dangerous-poki.zip` содержит Poki SDK и предназначен для дальнейшей проверки в Inspector.

## Команды

```sh
npm test                 # TypeScript + новая игровая логика
npm run build            # dist: локальная сборка
npm run build:poki       # dist: Poki-сборка
npm run release:local    # локальная сборка и ZIP
npm run release:poki     # Poki-сборка и ZIP
```

## Управление

- Нажимайте на монстра, чтобы ударить.
- Нажмите на вещь сбоку для покупки/прокачки. Снова нажмите на врага для закрытия окна и удара.
- Победите 10 врагов и нажмите «Вглубь». Каждая пятая комната — босс.
- Откройте инвентарь для просмотра добычи.
- Выйдите в гильдию в любой момент, продайте компоненты или сдайте 5 одинаковых за золото и репутацию.
- Нажмите на урон клика или «Тренировка», чтобы усилить ручной удар.

## Где продолжать разработку

Главный интерфейс — `src/idle/Game.tsx`. Игровая логика — `src/idle/engine.ts`. Концепт — `docs/project-concept.md`. Начните чтение документов с `docs/README.md`.

Старый экран в `src/game/Game.tsx` не используется. Сохранения старой игры не импортируются. Новый ключ: `idle-dangerous-save-v1`.

Это проверенный локальный прототип новой механики. Публикация, реальные рекламные показы, облачное сохранение и длительность полного прохождения требуют отдельной проверки. В `docs/QA.md` указан точный объём проведённых проверок.
